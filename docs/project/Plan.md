# Project Plan: ResearchOps

## Summary

ResearchOps는 연구 목표를 실행 가능한 작업으로 나누고, 근거를 수집·검증하여 출처를 추적할 수 있는 보고서로 만드는 Rust 기반 연구 운영 도구다. 작업이 중단되거나 검증에 실패해도 저장된 상태에서 재개하고, 미완료 범위를 드러내는 것을 제품의 핵심 가치로 삼는다.

채용 조사는 첫 활용 사례이며, 논문·기술 비교·시장 조사에도 같은 실행 엔진을 적용한다. 실시간 스크래핑은 교체 가능한 입력 어댑터다.

## Target users / personas

| 사용자 | 사용 상황 | 핵심 필요 |
| --- | --- | --- |
| 개인 연구자·구직자 | 여러 문서·공고·자료를 반복 비교 | 근거와 미확인 조건이 보이는 결과, 이전 작업 재개 |
| 조사 업무 운영자 | 정기·장기 실행과 보고서 전달을 관리 | 처리 전후 수량, 실패 단계, 재개 위치, 중복 전달 방지 |
| 시스템 개발자·검증자 | 연구 에이전트와 소스 어댑터를 연결 | 명시적 계약, 관측 가능한 실행 상태, 재현 가능한 장애 검증 |

## Purpose / value

세션 종료나 모델의 성공 문구를 업무 완료로 오인하지 않도록 한다. 실제 저장·재조회·역할별 완료 조건을 기준으로 결과를 판정하고, 완료되지 않은 항목과 다음 행동을 사용자가 확인할 수 있게 한다.

## Scope — product level

### In scope

| 역량 | 제품 범위 |
| --- | --- |
| 연구 목표와 범위 | 질문·소스·평가 기준·예산·완료 조건을 명시 |
| 지속 실행 | SQL 기반 큐, 임대와 토큰, 작은 묶음 처리, 체크포인트, 미완료 우선 복구 |
| 근거와 검증 | 출처 스냅샷, 원문 인용, 무결성 검사, 연구·검증 에이전트 간 피드백 |
| 정직한 완료 판정 | 시스템 실행 상태와 업무 완료를 분리하고 구체적 부분 완료 사유를 제공 |
| 결과와 전달 | 추적 가능한 보고서, 고정 서식·manifest 검사, 전달 어댑터의 중복 방지와 사후 확인 |

| 운영과 평가 | 실행 이력, 처리 전후 수량, 명시적 재개 위치, 장애 주입·품질 평가 |

### Non-goals and boundaries

| 경계 | 이유 |
| --- | --- |

| 모델 판단만으로 사실·지원 자격·보고서 전달을 확정 | 원문·저장·실제 전달 증거가 필요 |

| 첨부한 운영 지시를 즉시 production 작업으로 실행 | 구현 요구와 실제 권한·환경·데이터 검증을 구분 |

## Primary scenarios

| # | 사용자 | 흐름과 기대 결과 |
| --- | --- | --- |
| 1 | 개인 연구자 | 목표·질문·문서 입력 → 원문 근거 확인 → 보고서 내보내기 |
| 2 | 개인 연구자 | API 연결 테스트 → 연구 제안 → 별도 검증 → 반려 피드백·수정 → 근거가 연결된 결과 |
| 3 | 운영자 | 기존 미완료 조회 → 복구 가능한 작업 우선 처리 → 작은 묶음 저장·재조회 → 다음 단계 연속 실행 |
| 4 | 운영자 | 구체적 차단·한도 도달 → 부분 결과 보존 → 실제 오류·전후 수량·마지막 성공 단계·재개 위치 확인 |
| 5 | 채용 조사 운영자 | 국가·역할 범위별 탐색·검증·감사·평가 → 최신 근거와 적격성 조건에 따른 후보 분류 |
| 6 | 보고서 운영자 | 최신 평가·고정 템플릿·실제 본문 manifest 검증 → 중복 확인 → 허용된 전달 → 전달함 재조회·receipt 저장 |

## Feature boundaries for the initial cycle

첫 기능은 **execution-completion-contract**다. 공통 실행 지속성·저장 재조회·복구·완료 판정과, 연결되지 않은 외부 검증에 대한 명시적 차단을 다룬다.

채용별 탐색 경로·점수·원격 자격 정책, 실제 Supabase 연동, 고정 보고서 렌더러, Gmail 전달은 각각 필요한 입력과 승인된 인수 조건을 가진 후속 기능으로 분리한다. 공통 실행 계약의 구현만으로 이들 도메인 업무까지 완료됐다고 표시하지 않는다.

이 문서는 제품 방향을 정하며 구체적인 기능 인수 조건·설계·작업 체크리스트는 해당 기능의 문서와 GitHub 이슈에서 확정한다.

## Confirmed assumptions

- 개인 사용·로컬 실행을 우선하며 GitHub에서 공개 개발한다.
- Rust 코어와 현재 SQLite 기반 MVP를 출발점으로 삼고, 외부 서비스는 검증 가능한 어댑터로 확장한다.
- 첨부한 채용 운영 계약은 공통 실행 엔진과 채용·보고서 도메인 기능으로 분해한다.
- 첫 기능에서 실제 production 탐색·메일 발송을 수행하지 않으며, 연동·증거가 없으면 완료 조건을 차단한다.
